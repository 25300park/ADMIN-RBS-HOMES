PR `#$ARGUMENTS`를 **읽기 전용**으로 검토합니다. 수정, 커밋, 푸시, 머지, PR 코멘트 게시를 하지 않습니다.

## 읽을 것
1. `gh pr view $ARGUMENTS`와 `gh pr diff $ARGUMENTS`
2. 브랜치 이름이나 PR 설명에서 브리프 ID를 찾아 `docs/briefs/<ID>-*.md`
3. `docs/approval-policy.md`

## 확인할 것
- 변경 파일이 브리프의 **범위 안**에 있는가 (범위 이탈, 무관한 변경)
- 브리프의 "범위 밖"과 "금지 사항"을 어긴 것이 있는가
- 비밀값, 개인정보(IP, 이메일, 전화번호, 해시, 사용자 객체), 인증 우회가 코드나 로그, 테스트, 문서에 들어갔는가
- 인증, 권한, 발송, 환경변수, 스키마, AI 구조를 건드렸는가 (3등급 해당 여부와 등급 판정이 맞는가)
- 테스트가 **실제 코드**를 검증하는가 (가짜만 검증하는지, 수정 전 코드에서 실패하는지)
- 수용 기준마다 근거가 있는가, 실행하지 않은 것을 실행했다고 쓰지 않았는가
- 새 의존성, 되돌리기 어려운 변경

## 보고 (짧게)
1. **판단**: 승인 권장 / 보완 필요 / 반려 권장
2. 근거 5줄 이내
3. **대표가 직접 읽어야 할 파일과 줄**
4. 배포 후 대표가 확인할 것
5. 확인하지 못한 것
