입력: `$ARGUMENTS`

## 승인 확인 (가장 먼저)
- 첫 단어는 브리프 ID입니다. 나머지는 **대표의 결정 사항**입니다.
- 입력에 `승인`이라는 단어와 결정 사항이 없으면, 여기서 멈추고 무엇이 빠졌는지 묻습니다. 구현하지 않습니다.
- 결정 사항에 적힌 범위 밖의 것은 하지 않습니다.

## 시작
1. `docs/briefs/<ID>-*.md`, `docs/approval-policy.md`, `CLAUDE.md`(또는 `AGENTS.md`)를 읽습니다.
2. **`origin/main` 기준 별도 git worktree**에서 작업합니다. 레포 루트의 미커밋 변경은 건드리지 않습니다.
3. 브랜치는 `feat/<ID>-<slug>`(긴급 보안은 `fix/<ID>-<slug>`)입니다.
4. 브리프의 2, 3, 6번을 대표의 결정에 맞게 고칩니다.

## 구현
- 승인된 범위만 바꿉니다. 로직을 바꾸지 않는 작업(로그 삭제 등)에서는 다른 로직을 바꾸지 않습니다.
- 새 의존성, 스키마, 환경변수 변경은 브리프에 승인이 있을 때만 합니다.
- 테스트를 추가합니다. 새 테스트가 수정 전 코드에서 실패하는지 확인합니다. 가짜(mock)만 검증하는 테스트는 증거로 쓰지 않습니다.
- 로컬 DB만 씁니다. 운영 DB 접속, `.env*` 읽기, 비밀값 출력, 배포는 하지 않습니다.
- 커밋 메시지에 큰따옴표를 쓰지 않습니다.

## 검증 (실제로 실행한 것만 보고)
클린 빌드(`tsconfig.tsbuildinfo`와 `.next` 삭제 후), 타입체크, 린트, 전체 테스트, 브리프 수용 기준 항목별 확인. 화면 변경이 있으면 375px, 768px, 1440px.

## 마무리
1. **Draft PR**을 올립니다. 머지하지 않습니다. PR 설명에 변경 요약, 수용 기준별 결과, 확인하지 못한 것, 대표가 배포 후 확인할 것을 씁니다.
2. 브리프 10번(완료 보고)을 채웁니다. **11번(승인 기록)은 채우지 않습니다.**
3. 범위 밖 발견은 별도 목록으로 보고합니다.
4. worktree를 정리합니다.
